# TrenNex Android App

TrenNex is a native Android shopping application built with Kotlin. It includes phone authentication, product browsing, search, cart and wishlist persistence, account management, and map-based delivery addresses stored in Firebase Firestore.

## Features

- Phone-number login and OTP verification with Firebase Authentication
- Product, category, search, detail, cart, and wishlist experiences
- Local persistence with Room
- Account profile management backed by Firestore
- Google Maps and Places address search
- Current-location selection and reverse geocoding
- Saved Home/Office delivery addresses with edit and delete support
- Persistent selected delivery address

## Requirements

- Android Studio with JDK 11 support
- Android SDK 36
- An emulator or device running Android 10 (API 29) or later
- A Firebase Android app for package `com.example.trennex`
- A Google Maps Platform API key with **Maps SDK for Android** and **Places API** enabled

## Project setup

### 1. Clone the repository

```bash
git clone <repository-url>
cd Trennex-App
```

### 2. Configure Firebase

1. Create or open a Firebase project.
2. Register an Android app with package name `com.example.trennex`.
3. Download `google-services.json`.
4. Place it at:

```text
app/google-services.json
```

5. In Firebase Authentication, enable **Phone** as a sign-in provider.
6. Create a Cloud Firestore database.
7. Add the development and release SHA fingerprints in Firebase when testing real phone authentication.

> `google-services.json` contains project-specific configuration and should not be committed to a public repository.

### 3. Configure Google Maps and Places

Copy the example local configuration:

```bash
cp local.properties.example local.properties
```

Keep the `sdk.dir` generated by Android Studio, and set your API key:

```properties
sdk.dir=/path/to/Android/Sdk
MAPS_API_KEY=your_google_maps_platform_api_key
```

The build reads `MAPS_API_KEY` from `local.properties`. CI can provide the same value through the `MAPS_API_KEY` environment variable. Restrict the key in Google Cloud Console to the Android package name and signing-certificate SHA-1.

### 4. Build and run

Open the project in Android Studio, allow Gradle sync to finish, select the `app` configuration, and run it on an API 29+ device.

Command-line build:

```bash
./gradlew assembleDebug
```

## Saved-address data model

Addresses are stored under each authenticated user:

```text
users/{uid}/savedAddresses/{addressId}
```

Each saved address contains:

| Field | Purpose |
| --- | --- |
| `flatNo` | Flat, house, floor, or building detail |
| `address` | User-visible delivery address |
| `userName` | Recipient name |
| `mobile` | Recipient phone number |
| `addressType` | `Home` or `Office` label |
| `latitude` / `longitude` | Map pin coordinates |
| `placeName` | Short location title shown above the address |
| `createdAt` / `updatedAt` | Firestore server timestamps |

The selected address document ID is stored at `users/{uid}.selectedAddressId`.

### Editing address text versus map coordinates

The address text and map coordinates represent related but different information:

- Moving the map pin, selecting a Places result, or using current location changes the coordinates and refreshes the reverse-geocoded address.
- Editing the address text in the delivery bottom sheet changes the user-visible wording (for example, an entrance, landmark, or corrected house detail) while retaining the current map pin.
- Reopening an edited address restores the exact saved text and coordinates. Initial map restoration does not replace the saved text with a new Geocoder result.
- `addressType` only controls the Home/Office classification and icon; it does not determine latitude or longitude.

If the delivery point itself changes, move the pin or choose a new search result before saving. If only the written directions change, edit the text in the bottom sheet.

## Firestore development notes

The application expects authenticated users to access only their own profile and address documents. Configure production Firestore Security Rules accordingly. A minimal starting point is:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;

      match /savedAddresses/{addressId} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}
```

Review and harden these rules for your production data model before release.

## Project structure

```text
app/src/main/java/com/example/trennex/
├── data/          # Room entities/DAOs and remote models/services
├── repository/    # Product, cart, and wishlist repositories
├── ui/            # Fragments, adapters, dialogs, and UI state
├── utils/         # Shared stores and formatting helpers
└── viewmodel/     # Authentication, product, cart, search, and profile logic
```

Important address-flow files:

- `ui/home/HomeFragment.kt` loads Firestore addresses and starts edit mode.
- `ui/home/adapters/SaveAddressAdapter.kt` renders saved addresses and Home/Office icons.
- `ui/location/AddNewAddressFragment.kt` handles Maps, Places, reverse geocoding, bottom-sheet editing, and Firestore writes.
- `res/navigation/nav_graph.xml` defines the Safe Args values used to restore an address for editing.

## Troubleshooting

### Map is blank or Places suggestions do not load

- Confirm `MAPS_API_KEY` is present in `local.properties`.
- Enable Maps SDK for Android and Places API in the same Google Cloud project.
- Verify package-name and SHA restrictions.
- Confirm the device has network access and current Google Play services.

### Firebase login or Firestore calls fail

- Confirm `app/google-services.json` exists and belongs to `com.example.trennex`.
- Enable Phone Authentication and create Firestore in Firebase Console.
- Add the app signing SHA fingerprints.
- Check Firestore Security Rules for the signed-in user.

### Current location is unavailable

- Grant precise location permission.
- Enable device location services/GPS.
- Test on a device or emulator image with Google Play services.

## Security

Do not commit API keys, service-account files, production credentials, or user data. Use Android-restricted API keys and Firebase Security Rules, and rotate any credential that has been exposed.
