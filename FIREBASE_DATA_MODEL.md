# TrenNex Firebase Data Model

Status: proposed schema for Step 2. This document defines the data contract; Step 3 will implement Firebase configuration, rules, indexes, emulator support, and tests.

## Goals

- Own the complete TrenNex catalog instead of depending on DummyJSON.
- Preserve the current Android UI and user flows during migration.
- Keep public catalog reads fast and user data private.
- Prevent Android clients from changing prices, stock, coupons, payments, or order totals.
- Support variants, inventory, banners, reviews, coupons, notifications, and order history.
- Remain testable locally with the Firebase Emulator Suite.
- Allow future admin tooling without giving the mobile client catalog-write permission.

## Design rules

1. Use stable, non-sequential string document IDs. Existing numeric product IDs remain temporarily as `legacyId` for migration.
2. Store money as integer minor units (`priceMinor`, paise for INR), never floating-point values.
3. Store timestamps as Firestore `Timestamp` values generated by the server.
4. Store growing data such as variants, reviews, collection items, and notifications in subcollections.
5. Keep catalog documents small and consistent. Firestore documents have a 1 MiB maximum size.
6. Treat display snapshots as immutable historical data only inside orders; live cart prices are never authoritative.
7. Mobile clients may read public active catalog data but cannot write it.
8. Server operations own inventory, coupon redemption, order creation, payments, review eligibility, and aggregates.
9. Use `schemaVersion` on long-lived documents to support future migrations.
10. Never delete a parent document without explicitly deleting or retaining its subcollections.

## Collection tree

```text
products/{productId}
  variants/{variantId}
  reviews/{userId}

categories/{categoryId}

brands/{brandId}

banners/{bannerId}

homeSections/{sectionId}
  items/{itemId}

inventory/{variantId}

users/{uid}
  savedAddresses/{addressId}
  cartItems/{variantId}
  wishlistItems/{variantId}
  collections/{collectionId}
    items/{variantId}
  notifications/{notificationId}

orders/{orderId}
  items/{itemId}
  events/{eventId}

coupons/{couponId}
  redemptions/{uid}

appConfig/{configId}

adminAuditLogs/{logId}
```

## Public catalog

### `products/{productId}`

Use a stable scattered ID such as `prd_8f3k2m9q`; do not use sequential IDs such as `product1`, `product2`, and so on.

| Field | Type | Required | Description |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1`. |
| `legacyId` | integer | migration | Current DummyJSON-compatible ID. Indexed during migration. |
| `slug` | string | yes | Human-readable stable slug; unique enforcement is handled by admin tooling. |
| `name` | string | yes | Product title. |
| `normalizedName` | string | yes | Lowercase normalized value for deterministic sorting/prefix support. |
| `shortDescription` | string | yes | Card/summary description. |
| `description` | string | yes | Full product description. Exempt from indexing. |
| `brandId` | string | no | Reference ID into `brands`. |
| `categoryId` | string | yes | Primary leaf category ID. |
| `categoryPath` | array<string> | yes | Ancestor IDs, for example `['fashion','men','jackets']`; keep small. |
| `tags` | array<string> | no | Controlled merchandising/search tags. |
| `searchTerms` | array<string> | no | Small normalized exact-token set for basic search; not a full-text engine. |
| `thumbnail` | map | yes | `{ storagePath, url, altText }`. |
| `images` | array<map> | yes | Small ordered gallery of `{ storagePath, url, altText, sortOrder }`. |
| `currency` | string | yes | `INR`. |
| `minPriceMinor` | integer | yes | Lowest active variant selling price in paise; server-maintained. |
| `maxPriceMinor` | integer | yes | Highest active variant selling price in paise; server-maintained. |
| `minMrpMinor` | integer | yes | Lowest active variant MRP in paise. |
| `discountPercent` | number | yes | Display aggregate; server-maintained. |
| `ratingAverage` | number | yes | Server-maintained aggregate, default `0`. |
| `ratingCount` | integer | yes | Server-maintained aggregate, default `0`. |
| `reviewCount` | integer | yes | Server-maintained aggregate, default `0`. |
| `availability` | string | yes | `IN_STOCK`, `LOW_STOCK`, `OUT_OF_STOCK`, or `PREORDER`; server-maintained. |
| `shippingInformation` | string | no | Customer-facing delivery information. |
| `warrantyInformation` | string | no | Warranty text. |
| `returnPolicy` | string | no | Return-policy text. |
| `specifications` | map<string, string> | no | Bounded specification map. Exempt from indexing. |
| `dimensions` | map | no | `{ widthCm, heightCm, depthCm, weightGrams }`. |
| `status` | string | yes | `DRAFT`, `ACTIVE`, or `ARCHIVED`. Mobile queries require `ACTIVE`. |
| `featured` | boolean | yes | Supports curated queries. |
| `newArrival` | boolean | yes | Supports home merchandising. |
| `sortOrder` | integer | yes | Admin-controlled tie-break order. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |
| `publishedAt` | timestamp | no | First publication time. |

Compatibility mapping:

```text
ProductResponse.id                 <- legacyId
ProductResponse.title              <- name
ProductResponse.price              <- minPriceMinor / 100.0 (temporary adapter only)
ProductResponse.images             <- images[].url
ProductResponse.thumbnail          <- thumbnail.url
ProductResponse.discountPercentage <- discountPercent
ProductResponse.category           <- categoryId or resolved category slug
ProductResponse.brand              <- resolved brand name
ProductResponse.colors/variants    <- variants subcollection
ProductResponse.reviews            <- reviews subcollection
```

### `products/{productId}/variants/{variantId}`

Each purchasable SKU is one variant. A product with no visible choices still has one default variant.

| Field | Type | Required | Description |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1`. |
| `productId` | string | yes | Denormalized parent ID for server jobs and collection-group queries. |
| `sku` | string | yes | Stable unique SKU, enforced by admin tooling. |
| `name` | string | yes | Variant display label. |
| `attributes` | map<string, string> | yes | Example: `{ color: 'Onyx Black', storage: '256 GB' }`. |
| `attributeSort` | map<string, integer> | no | Stable option ordering. |
| `priceMinor` | integer | yes | Selling price in paise. |
| `mrpMinor` | integer | yes | MRP in paise; must be at least `priceMinor`. |
| `currency` | string | yes | `INR`. |
| `image` | map | no | Variant-specific image reference. |
| `barcode` | string | no | Admin/inventory use. |
| `active` | boolean | yes | Whether this SKU can be selected. |
| `sortOrder` | integer | yes | Option display order. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

Exact stock quantity is intentionally not stored here. The public variant can expose only derived availability.

### `categories/{categoryId}`

| Field | Type | Required | Description |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1`. |
| `slug` | string | yes | Stable category slug. |
| `name` | string | yes | Display name. |
| `parentId` | string/null | yes | `null` for root categories. |
| `path` | array<string> | yes | Ancestor path including this category. |
| `level` | integer | yes | Root is `0`. |
| `icon` | map | no | Storage path, URL, and alt text. |
| `heroImage` | map | no | Optional category header image. |
| `description` | string | no | Exempt from indexing. |
| `active` | boolean | yes | Public visibility. |
| `sortOrder` | integer | yes | Navigation order. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

Initial root IDs should align with the app/Figma taxonomy: `top-picks`, `fashion`, `appliances`, `mobiles`, `electronics`, `home`, `beauty`, `furniture`, `toys-books`, and `sports`.

### `brands/{brandId}`

Fields: `schemaVersion`, `slug`, `name`, `logo`, `description`, `active`, `sortOrder`, `createdAt`, and `updatedAt`.

### `banners/{bannerId}`

| Field | Type | Required | Description |
|---|---|---:|---|
| `title` | string | yes | Accessible title. |
| `subtitle` | string | no | Promotional copy. |
| `image` | map | yes | Storage path, URL, and alt text. |
| `actionType` | string | yes | `NONE`, `PRODUCT`, `CATEGORY`, `SEARCH`, or `EXTERNAL_URL`. |
| `actionValue` | string | no | Target ID/query/approved URL. |
| `placement` | string | yes | Example: `HOME_HERO`. |
| `active` | boolean | yes | Visibility. |
| `startAt` | timestamp | no | Campaign start. |
| `endAt` | timestamp | no | Campaign end. |
| `sortOrder` | integer | yes | Display order. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

### `homeSections/{sectionId}`

Fields: `title`, `type`, `active`, `sortOrder`, `maxItems`, `queryConfig`, `createdAt`, and `updatedAt`.

Supported `type` values:

- `CURATED_PRODUCTS`: use `items` subcollection containing ordered product/variant references.
- `CATEGORY_PRODUCTS`: use a bounded `queryConfig` with `categoryId` and sort mode.
- `FEATURED_PRODUCTS`: query active featured products.
- `NEW_ARRIVALS`: query active new arrivals.

`homeSections/{sectionId}/items/{itemId}` fields: `productId`, optional `variantId`, `sortOrder`, `active`, `createdAt`.

## Inventory and server-owned commerce data

### `inventory/{variantId}`

Document ID equals the variant ID.

| Field | Type | Required | Description |
|---|---|---:|---|
| `productId` | string | yes | Product reference. |
| `sku` | string | yes | SKU snapshot. |
| `onHand` | integer | yes | Physical stock. |
| `reserved` | integer | yes | Temporarily reserved stock. |
| `available` | integer | yes | Server-maintained `onHand - reserved`. |
| `lowStockThreshold` | integer | yes | Alert threshold. |
| `allowBackorder` | boolean | yes | Backorder policy. |
| `updatedAt` | timestamp | yes | Server timestamp. |

Rules: mobile clients cannot read exact quantities or write this collection. Checkout/inventory functions use transactions because available stock depends on the current document value.

### `coupons/{couponId}`

Fields:

- `codeHash` or normalized code lookup managed by the server.
- `name`, `description`, `type` (`PERCENT`, `FIXED`, `FREE_SHIPPING`).
- `value`, `maxDiscountMinor`, `minimumSubtotalMinor`, `currency`.
- `eligibleProductIds`, `eligibleCategoryIds`, `excludedProductIds` as bounded lists.
- `perUserLimit`, `totalLimit`, `redemptionCount`.
- `active`, `startAt`, `endAt`, `createdAt`, `updatedAt`.

`coupons/{couponId}/redemptions/{uid}` contains `count`, `lastOrderId`, and `updatedAt`. Validation and updates are server-only.

## User-owned data

### `users/{uid}`

| Field | Type | Required | Description |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1`. |
| `displayName` | string | yes | User-editable profile name. |
| `phoneE164` | string | yes | Verified phone number from Auth. |
| `email` | string/null | yes | Optional email. |
| `photoUrl` | string/null | yes | Optional profile image. |
| `selectedAddressId` | string/null | yes | Current delivery address. |
| `preferences` | map | no | Locale/theme/notification preferences. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |
| `lastLoginAt` | timestamp | yes | Server-maintained. |

Administrative authorization must use Firebase Authentication custom claims or a protected server-owned role record. The mobile client must never be able to grant itself an admin role by editing `users/{uid}`.

### `users/{uid}/savedAddresses/{addressId}`

This preserves the current app contract while normalizing field names.

Fields: `label` (`HOME`, `OFFICE`, `OTHER`), `recipientName`, `phoneE164`, `flatNo`, `addressLine`, `landmark`, `locality`, `city`, `state`, `postalCode`, `countryCode`, `location` (GeoPoint), `placeName`, `isDefault`, `createdAt`, `updatedAt`, and `schemaVersion`.

Migration aliases from the current data: `userName -> recipientName`, `mobile -> phoneE164`, `address -> addressLine`, and latitude/longitude -> `GeoPoint`.

### `users/{uid}/cartItems/{variantId}`

| Field | Type | Required | Description |
|---|---|---:|---|
| `productId` | string | yes | Product reference. |
| `variantId` | string | yes | Variant reference and document ID. |
| `quantity` | integer | yes | `1..10` initially. |
| `selected` | boolean | yes | Checkout selection state. |
| `addedAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

No authoritative price is stored in the cart document. The app may display cached Room snapshots offline, but checkout re-reads live server prices.

### `users/{uid}/wishlistItems/{variantId}`

Fields: `productId`, `variantId`, `addedAt`, and optional `source`. Product title/image/price are resolved from catalog data or local cache.

### `users/{uid}/collections/{collectionId}`

Fields: `name`, `normalizedName`, `itemCount`, `coverProductIds` (maximum four), `createdAt`, `updatedAt`, and `schemaVersion`.

`users/{uid}/collections/{collectionId}/items/{variantId}` fields: `productId`, `variantId`, and `addedAt`.

This replaces the current unbounded JSON-encoded `items` list in `CollectionEntity`/Firestore representations.

### `users/{uid}/notifications/{notificationId}`

Fields: `type`, `title`, `body`, `imageUrl`, `actionType`, `actionValue`, `readAt`, `createdAt`, and optional `expiresAt`. Server creates notifications; the owner may read them and update only `readAt`.

## Orders

### `orders/{orderId}`

Orders are top-level so server/admin queries do not require scanning every user subcollection. Mobile queries must include `whereEqualTo('userId', uid)` because Security Rules authorize queries; they do not filter unauthorized documents.

| Field | Type | Required | Description |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1`. |
| `orderNumber` | string | yes | Human-readable server-generated number, not the document ID. |
| `userId` | string | yes | Owner UID. |
| `status` | string | yes | `PENDING_PAYMENT`, `CONFIRMED`, `PROCESSING`, `SHIPPED`, `OUT_FOR_DELIVERY`, `DELIVERED`, `CANCELLED`, or `REFUNDED`. |
| `currency` | string | yes | `INR`. |
| `subtotalMinor` | integer | yes | Server calculated. |
| `discountMinor` | integer | yes | Server calculated. |
| `shippingMinor` | integer | yes | Server calculated. |
| `taxMinor` | integer | yes | Server calculated. |
| `totalMinor` | integer | yes | Server calculated. |
| `coupon` | map/null | yes | Immutable applied-coupon snapshot. |
| `shippingAddress` | map | yes | Immutable address snapshot. |
| `recipient` | map | yes | Immutable name/phone snapshot. |
| `payment` | map | yes | Method and safe provider references; never store card/UPI secrets. |
| `itemCount` | integer | yes | Summary count. |
| `preview` | map | yes | First-item title/image for order list UI. |
| `expectedDeliveryAt` | timestamp/null | yes | Server estimate. |
| `placedAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

### `orders/{orderId}/items/{itemId}`

Immutable purchase snapshots: `productId`, `variantId`, `sku`, `name`, `variantName`, `attributes`, `imageUrl`, `quantity`, `unitPriceMinor`, `unitMrpMinor`, `discountMinor`, `lineTotalMinor`, `returnPolicy`, and `reviewStatus`.

### `orders/{orderId}/events/{eventId}`

Fields: `status`, `title`, `description`, `location`, `visibleToCustomer`, `createdAt`, and `createdBy`. Server/admin write only; owner read only.

## Reviews

### `products/{productId}/reviews/{userId}`

Using the UID as the document ID enforces one active review per user per product.

Fields: `userId`, `orderId`, `rating` (`1..5`), `title`, `comment`, `displayName`, `verifiedPurchase`, `status` (`PENDING`, `PUBLISHED`, `REJECTED`), `createdAt`, and `updatedAt`.

Review submission should use a callable server function that verifies the user owns a delivered order containing the product. Rating aggregates on the product are server-maintained.

## Configuration and audit

### `appConfig/public`

Public read-only configuration: minimum supported app version, maintenance flags, support links, feature flags safe for clients, and legal-document versions.

### `adminAuditLogs/{logId}`

Server-only append records for catalog, price, inventory, coupon, and order-status changes. Fields: actor UID/service, action, entity path, before/after summaries, request ID, and timestamp.

## Query catalog and planned composite indexes

Exact index files are created in Step 3, after repository queries are finalized.

| Use case | Query | Expected composite index |
|---|---|---|
| Home featured products | `products: status == ACTIVE, featured == true, sortOrder asc` | `status + featured + sortOrder` |
| New arrivals | `products: status == ACTIVE, newArrival == true, publishedAt desc` | `status + newArrival + publishedAt` |
| Category listing | `products: status == ACTIVE, categoryId == X, sortOrder asc` | `status + categoryId + sortOrder` |
| Category price sort | `products: status == ACTIVE, categoryId == X, minPriceMinor asc/desc` | `status + categoryId + minPriceMinor` |
| Category rating sort | `products: status == ACTIVE, categoryId == X, ratingAverage desc` | `status + categoryId + ratingAverage` |
| Active banners | `banners: placement == X, active == true, sortOrder asc` | `placement + active + sortOrder` |
| User orders | `orders: userId == uid, placedAt desc` | `userId + placedAt` |
| User orders by status | `orders: userId == uid, status == X, placedAt desc` | `userId + status + placedAt` |
| Unread notifications | user subcollection: `readAt == null, createdAt desc` | `readAt + createdAt` if required |

Full-text search is not implemented by native Firestore querying. Initial exact/category/tag search can use normalized fields and a small token list. A production-grade full-text search phase should synchronize public product data to a dedicated search service rather than downloading the entire catalog.

## Access-control matrix

| Path | Anonymous | Authenticated owner | Admin/server |
|---|---|---|---|
| Active `products`, variants, categories, brands, banners, home sections | read | read | read/write |
| Draft/archived catalog | deny | deny | read/write |
| `inventory` | deny | deny exact quantities | read/write |
| `users/{uid}` | deny | read/update allowed profile fields | read/write |
| User cart/wishlist/collections/addresses | deny | read/write own documents with validation | read/write |
| User notifications | deny | read; update `readAt` only | create/read/write |
| `orders` | deny | read own orders only | create/read/write |
| Order items/events | deny | read when parent order belongs to user | create/read/write |
| Coupons/redemptions | deny direct validation/write | callable validation only | read/write |
| Reviews | published reviews readable | callable create/update for eligible purchase | moderate/read/write |
| App public config | read | read | write |
| Audit logs | deny | deny | append/read |

## Secure server operations planned for Step 8

- `createOrder`: validate auth, cart items, live prices, coupon, address, and stock; reserve inventory atomically; create order and items.
- `confirmPayment`: verify provider webhook/callback and transition order status safely.
- `cancelOrder`: validate state and release inventory.
- `validateCoupon`: return only eligibility/result needed by the caller.
- `submitReview`: confirm delivered purchase and update rating aggregates.
- `markOrderStatus`: admin-only status transition and customer notification.
- `publishCatalogItem`: admin-only validation and aggregate updates.

Callable functions are preferred for app-initiated privileged operations because Firebase Auth and App Check tokens can be included and validated by the callable protocol.

## Migration from the current app

1. Keep existing `products`, `categories`, and user subcollections readable during migration.
2. Seed the new catalog with stable `productId` and `variantId` values while preserving `legacyId`.
3. Add Android DTO/domain adapters so the UI can continue receiving the current `ProductResponse` shape temporarily.
4. Migrate cart and wishlist numeric IDs to variant IDs, resolving through `legacyId` during a one-time migration.
5. Move collection item arrays/JSON into collection `items` subcollections.
6. Create top-level orders from existing `users/{uid}/orders` records, retaining legacy order IDs where possible.
7. Change repositories to the new schema behind interfaces and feature flags.
8. Compare Firebase and DummyJSON results during development.
9. Disable the DummyJSON fallback only after catalog, search, detail, cart, wishlist, and order tests pass.
10. Remove legacy fields only in a later schema version.

## Step 2 decisions

- Firestore is the source of truth for catalog content.
- Firebase Storage holds product/category/banner media.
- Product variants are subcollection documents.
- Exact inventory is a protected top-level collection keyed by variant ID.
- Money uses integer paise and `INR` currency codes.
- User cart and wishlist documents reference variants instead of duplicating mutable price data.
- Orders are top-level, server-created documents with immutable item snapshots.
- Reviews require a delivered purchase and server validation.
- Coupons and inventory are never trusted from the Android client.
- Full-text search will require a dedicated search solution when the catalog outgrows controlled token search.
